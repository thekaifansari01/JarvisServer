Getting Started › Introduction

Introduction

JARVIS is an open-source autonomous AI operating system for Windows. It reads codebases, sends emails, controls your Android phone, remembers you across months, and re-plans mid-task when you interrupt. This documentation covers everything from installation to advanced configuration.

sync

Live Correction

Interrupt mid-run. Completed steps stay intact.

memory

Lifelong Memory

Five-tier memory with weighted graph + hybrid RAG.

extension

MCP Native

18,000+ community servers via a single JSON entry.

record_voice_over

Dual-Engine Voice

Azure on-device + Vosk fallback, zero cloud round-trip.

developer_board

4GB RAM

Verified on a 2012 Intel i5-3210M laptop.

phone_android

Android Control

WebSocket bridge — calls, SMS, GPS, torch, clipboard.

Who is this for?link

JARVIS is built for developers and power users who want an AI that actually does things — not just chats. If you want to:

  • Automate real work across your PC, phone, and communications
  • Run an AI agent on modest hardware (no GPU required)
  • Extend capabilities without touching code (via MCP)
  • Keep all memory and data on your own disk
  • Use any OpenAI-compatible LLM, including local models

Then this is for you. If you need a polished IDE copilot, use Claude Code or Cursor.

info

Windows-only. JARVIS relies on Windows APIs for GUI automation, PC monitoring, and the Termux bridge. Mac/Linux support is on the roadmap.

translate

About the voice examples. JARVIS responds in your language. Some voice commands and agent responses in these docs appear in Hinglish (Hindi + English) — that's because the developer is Indian and this is the language he actually uses daily. You can configure JARVIS to respond in any language you prefer.

terminalpowershell

terminalpowershell

6. Enable MCP (optional)link

To add external tools via the Model Context Protocol, create Data/mcp_servers.json. See the MCP section for full details.

Configuration › Voice Setup

Voice Setup

JARVIS ships with dual-engine wake word detection, premium STT, and low-latency TTS. Everything runs on-device by default — no cloud round-trip for wake word.

checklist
Before you start
  • Working microphone connected
  • Deepgram API key for STT
  • Optional: Azure Speech account (for higher accuracy wake word)
  • Optional: TTS API key (Sarvam) — falls back to Edge TTS

Wake word engineslink

Two independent engines, auto-selected on boot:

EngineWhen activeAccuracy
Azure Custom KeywordIf Data/model/azure/jarvis.table exists97%+
Vosk KWSFallback if Azure unavailable~66%

Building an Azure wake modellink

This is a one-time 30-minute process. After training, no API key or network call is needed for wake word.

  1. Create a Foundry resourceGo to Azure Portal → Foundry → Speech. Copy your key and region.
  2. Train a Custom KeywordOpen Speech Studio → Custom Keyword → Create project (English US).
  3. Choose your modelBasic (~30 min queue) or Advanced (~48h for better accuracy).
  4. Download the .table fileExtract the .table from the zip and save as Data/model/azure/jarvis.table.
  5. Restart JARVISAzure engine activates automatically. Check startup logs for confirmation.
info

No Azure subscription? Vosk works out of the box. It auto-downloads a small model on first run — no config required.

Speech-to-textlink

STT uses Deepgram Nova-2 with a self-healing LTM vocabulary cache. Entity names from your memory graph are auto-synced into Deepgram's vocabulary, so it correctly recognizes names, projects, and jargon over time.

check_circle

Zero training needed. Add someone to your memory and Deepgram starts recognizing their name within a session.

Text-to-speechlink

Default TTS uses Sarvam for English + Hinglish (low-latency). Falls back to Edge TTS if the API key is missing. First audio typically lands in 0.8–2 seconds.

Memory & RAG

JARVIS has five tiers of memory — from verbatim message history to long-term semantic graphs and hybrid RAG over your documents.

The five tierslink

#TierWhat it storesRetention
1EpisodicRaw messages + execution logs15 days (2 raw + 13 summarized)
2SemanticWeighted property graph (facts, people, contacts)Lifetime, with decay
3RAGIndexed documents via hybrid BM25 + vectorUntil deleted
4Ephemeral10-min TTL artifacts (last screenshot, generated image)Auto-purged
5BehavioralPatterns extracted from your habits & routinesLifetime, with decay

RAG Indexer Dashboardlink

JARVIS ships with a web dashboard for managing indexed folders and filters. Open it after launching:

languagebrowser 
http://127.0.0.1:8080

On first boot, the indexer auto-adds your Documents folder. You can add more from the Folders tab — paste any absolute path and click Add & Index.

Adding a new folderlink

  1. Open the dashboard at 127.0.0.1:8080.
  2. Go to Folders tab.
  3. Paste an absolute path, e.g. D:/Projects or C:\Users\You\Desktop\notes.
  4. Click Add & Index. Progress streams live.
warning

System paths are auto-blocked. Paths like C:\Windows, Program Files, and dev garbage (node_modules, .git, venv) are skipped automatically. Sensitive paths like .ssh and .aws trigger warnings.

Filters & exclusionslink

Open the Filters tab to tune indexing:

  • Max file size — default 5 MB. Larger files are skipped.
  • Max depth — how deep to recurse.
  • Custom ignore patterns — e.g. *.log, backup_*, node_modules.

Rebuilding the indexlink

If embeddings feel stale or you changed the model:

terminalpowershell 
# Purge the vector index
Remove-Item -Recurse -Force Data\jarvis_memory\rag_chroma_db
Remove-Item Data\jarvis_memory\rag_hashes.json

# Restart JARVIS to rebuild automatically
jarvis

Integrations › MCP Servers

MCP Integration

The Model Context Protocol lets JARVIS plug into 18,000+ community-built tool servers — GitHub, Brave Search, SQLite, Postgres, Notion, Slack, Docker, Puppeteer, and more — via a single JSON file.

checklist
Before you start
  • Node.js 18+ (24+ recommended for newest servers)
  • pip install mcp completed
  • API keys only if the chosen MCP server requires them

How it workslink

When Data/mcp_servers.json exists with valid configs, JARVIS:

  • Spawns each configured MCP server as a subprocess
  • Performs a JSON-RPC handshake to discover tools
  • Converts tool schemas into native function declarations
  • Exposes them to the agent as mcp__<server>__<tool>

One-liner CLI & live hot-reloadlink

Add, remove, test, or toggle MCP servers directly from your terminal. If JARVIS is running, changes are hot-reloaded in the background within 2 seconds with zero restarts:

terminalpowershell 
# Add an NPX or Python MCP server
jarvis mcp add everything npx @modelcontextprotocol/server-everything

# Add a server with environment variables
jarvis mcp add github npx @modelcontextprotocol/server-github -e GITHUB_PERSONAL_ACCESS_TOKEN=ghp_xxx

# List, test, disable, enable, or remove servers live
jarvis mcp list
jarvis mcp test everything
jarvis mcp disable everything
jarvis mcp enable everything
jarvis mcp remove everything

JSON configuration examplelink

You can also edit Data/mcp_servers.json directly (saved changes auto-sync live):

descriptionmcp_servers.json 
{
  "mcpServers": {
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": {
        "GITHUB_PERSONAL_ACCESS_TOKEN": "ghp_xxxxxxxxxxxx"
      },
      "call_timeout": 60
    },
    "sqlite": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-sqlite", "C:/data/mydb.sqlite"]
    }
  }
}

Startup or live hot-reload logs confirm the active tools immediately:

terminalstartup log 
MCP: server 'github' connected (40 tools).
MCP: server 'sqlite' connected (6 tools).
MCP: ready with 46 tools from 2 servers.

info

JARVIS automatically resolves npx shims on Windows directly to node.exe + npx-cli.js and injects -y automatically — no cmd /c wrapper needed.

Android Bridge

Control your Android phone natively from Windows using Termux and a WebSocket bridge. No SSH required, no cloud relay.

checklist

Reference › Architecture

Architecture

JARVIS is resilient by design. Every layer has a fallback; every provider has a failover; every tool has a watchdog.

Dual-brain routinglink

A semantic router picks the right brain for each command:

BrainWhenLatency
FastBrainShort commands, OS toggles, casual chat<2s
AgenticBrainComplex engineering, comms, memory, visionMulti-step

3-tier fallback chainlink

  1. Tier 1 — Semantic Router Cloud-based; classifies intent via a fast LLM.
  2. Tier 2 — FastBrain If the router API times out, FastBrain handles routing.
  3. Tier 3 — Local rule-based If both fail, keyword + heuristic rules take over.

Provider failoverlink

Every LLM call tries PrimaryProvider first. On failure (timeout, rate limit, 5xx), it retries FallbackProvider — a completely separate OpenAI-compatible endpoint. Configure both in .env.

ServiceWatchdoglink

Monitors and auto-restarts:

  • STT Popup, Baileys WhatsApp server
  • Mobile Bridge (:8090), Telegram bot
  • Indexer Dashboard (:8080), MCP Manager

Crashes trigger a cooldown backoff. Unauthenticated services are skipped, not restarted endlessly.

The Agent Panel

The Agent Panel is JARVIS's floating command center — a premium always-on-top overlay that shows exactly what the agent is thinking, which tool it's running, how many tokens it has consumed, and when it needs your permission before doing something irreversible. It is not a chat window. It is a live observability layer over the autonomous loop.

psychology

Live Thought Stream

Watch reasoning unfold in real-time with syntax-highlighted markdown.

verified_user

HITL Consent Gates

Approve, edit, or cancel every WhatsApp, Telegram, or Email before it sends.

sync

Non-Blocking

Panel never interrupts the agent — it's read-only until a decision is required.

palette

Action-Aware Theming

Every tool has its own icon, color, and pulse animation.

info

Read-only by design. The Agent Panel is not a chat window — you can't type into it. Commands come from voice, Ctrl+Shift+J, or the Telegram bot. The panel observes and, when needed, asks for approval.

When It Appearslink

  • Auto-spawns on every agent loop start — voice command, Ctrl+Shift+J, Telegram bot, MCP tool call
  • Stays visible while hide_timer is active (4-second idle cooldown)
  • Fades out after 4 seconds of no activity — unless awaiting confirmation
  • Reappears instantly on next status update
  • Never blocks the underlying desktop — it's Qt.Tool, no taskbar entry, no focus steal
  • Bypasses the 4-second timer entirely when a confirmation is pending
warning

The panel cannot be "closed" manually while the agent runs — it dismisses itself. To hide permanently, stop JARVIS from the CLI.

The Thought Streamlink

The main body of the panel renders the agent's live reasoning as formatted markdown. It supports:

  • Fenced code blocks with syntax highlighting — Python, JS, SQL, C++, Go, Rust, Shell (auto-detected regex)
  • Tables with alignment detection
  • Headings, bold, italic, strikethrough
  • Inline code chips and clickable links (open in external browser)
  • Bullet + numbered lists with nested indentation
  • Blockquotes (nested depth supported)
  • Checkbox lists — [ ] → ☐, [x] → ☑
info

Scroll lock behavior. Auto-scrolls to bottom unless you've manually scrolled up. Scrolling up "locks" the view; new content won't pull you down until the step counter increments. After 5,000 chars, older content is safely trimmed — mid-code-fence and mid-table cuts are auto-healed.

The Observation Cardlink

When a tool returns an observation string, the panel shows a dedicated card below the thought stream:

  • Max height: 90px (elided to 155 chars)
  • Accent-colored left bar matches current action color
  • Auto-hides when next thought arrives or task completes
  • Separated from thought stream by a hairline divider

Human-in-the-Loop Confirmationlink

This is the trust anchor. When the agent needs to send an irreversible action — WhatsApp message, Telegram, Email, or destructive file operation — the panel raises a premium confirmation card that cannot be bypassed.

gpp_maybe

Never bypassed. Even if the user says "just do it" in the voice prompt, email_action, whatsapp_action, and telegram_action always raise the confirmation card. The agent cannot auto-approve its own outgoing messages. This is enforced at the ZMQ boundary, not in the prompt.

Lifecycle & Shutdown

JARVIS ships 7 background services, 3 Qt overlays, a Node.js bridge, and dozens of subprocesses. Every one of them needs to die cleanly — but the memory graph, behavioral patterns, and session state must survive. The lifecycle system is a 14-step graceful shutdown choreography guarded by an idempotent flag, 7 signal handlers, and a parallel service-teardown that completes in ~2.6 seconds.

The 14-Step Shutdown Sequencelink

Every shutdown follows the same 6-phase choreography. Each phase is guarded — if it fails, the next still runs.

Phase 5Parallel Teardown→7 services killed in parallel, 2.5s max each

bolt

Parallel teardown = 7× speedup. 7 services × 2.5s timeout = 17.5s if sequential. But stop_all_services() spawns 7 threads — total wall-clock is ~2.5s regardless of count. Shutdown stays under 3 seconds on any hardware.

info

But JARVIS has already done all cleanup manually. os._exit() skips everything — guaranteeing no stray handler accidentally respawns a thread or writes to a corrupted state during teardown.

Command Handler Guardslink

Commands behave deterministically during shutdown — no half-executed side effects:

  • Pre-check: if is_shutting_down(): return — drops incoming commands immediately
  • Mid-check: After process_command(), another check — if shutdown started mid-processing, actions aren't executed
  • Interrupt check: if interrupt.is_interrupted(): return — voice interrupt support
  • Empty guard: Empty strings and None dropped before processing
info

Dual shutdown check. The handler checks is_shutting_down() twice — before and after process_command(). A 5-second AgenticBrain task that started before shutdown won't execute its side effects if shutdown triggers mid-run. Critical: you don't want an email going out after Ctrl+C.

  • Embedding model load ~14s. The first cold start after reboot is noticeably slower than subsequent starts.
  • Deep-planner tasks dominate CPU. Multi-step agentic reasoning for 8+ minutes pegs one CPU core at 100% on the 2012 laptop.
  • Qt overlays animate at 60fps only on capable GPUs. On integrated graphics, panel animations drop to 30fps during heavy load.

  • No multi-user support. JARVIS is single-user, single-machine. No shared memory, no team features.

  • No automatic upgrades. You manage updates via git pull. No auto-update mechanism.
  • No enterprise support. Solo developer, no SLAs, no paid support tiers. Best-effort community support via GitHub issues.
  • No real-time collaboration. Not a Google Docs for AI — one user, one agent, one machine.
  • No video input analysis. Images and screenshots only. Video frames are extracted one-by-one via ffmpeg but the tool is not optimized for video.
  • No native mobile app. Android control requires Termux from F-Droid. iOS is not supported at all.

Security & privacy boundaries

security

Recommendation: review execute_terminal_command behavior before enabling on a machine with sensitive credentials.

  • API keys stored in .env are plaintext unless you encrypt them yourself. Telegram bot tokens use AES encryption.
  • Conversation history is plaintext JSONL in Data/jarvis_memory/. Encrypt the disk if you handle sensitive data.
  • Cloud LLM calls send your prompts to Groq/OpenRouter/Gemini. Use local models for zero-knowledge privacy.

Customizing AgenticBrain (AGENT_SYSTEM_PROMPT)

The AgenticBrain prompt is a large XML-structured block near the bottom of Prompts.py. It contains critical safety, escalation, and tool-selection rules. Modify carefully.

Sections you can safely edit

  • identity — <role>You are Jarvis...</role> — describes the AI personality
  • language_and_tone_directive — final response language and style rules
  • error_recovery_and_debugging — retry strategy descriptions

Sections you must NOT edit

gpp_maybe

These are load-bearing. Editing them causes silent breakage:

  • {max_steps} and {panic_step} placeholders inside <budget_aware_planning> — formatted by build_agentic_system_prompt()
  • <auth_and_api_failure_handling> block — prevents retry loops on missing credentials
  • <tool_selection_hierarchy> — the fallback chain for tool priority
  • <definition_of_done> — completion verification rules
  • <intelligence_core_workflow> — the 4-pillar reasoning contract

Placeholders in AGENT_SYSTEM_PROMPT

Two placeholders are dynamically formatted at runtime by build_agentic_system_prompt() from core/brain/prompts.py:

PlaceholderReplaced withSource

{panic_step}Step number triggering panic modemax_steps - 2

If you remove these placeholders, the dynamic formatter will raise KeyError at loop start and the agent will fail to initialize.

How domain modules are injected

The base prompts above are the skeleton. At runtime, JARVIS appends domain-specific rules to them via two builder functions in core/brain/prompts.py:

  • build_fast_system_prompt(base_system_prompt, domains, raw_command) — appends rules for the detected domain
  • build_agentic_system_prompt(base_agent_prompt, domains, raw_command, context, max_steps, panic_step) — formats placeholders and injects behavioral modules

The semantic router determines which domains are active (e.g., coding, ui_design, communication, scheduling, gui_automation). Each domain prepends additional system rules before the LLM call.

info

Domain rules live separately. If you want to tune behavior for a specific domain (like coding style), edit the domain rule registry in core/brain/prompts.py — not Prompts.py. This keeps edits isolated from the base prompt.

Bring Your Own Tool

JARVIS supports two distinct paths for adding new capabilities. MCP is the recommended path — zero code changes, live hot-reload, and no restart. Native tools require editing two Python files but give deeper access to JARVIS internals.

checklist
Before you start
  • For MCP: Node.js 18+ and pip install mcp
  • For native: Python 3.10+ and JARVIS installed
  • Basic familiarity with JSON

Which path should you pick?

ScenarioRecommendedWhy
Wrap an API, CLI, or databaseMCPZero code changes, hot-reload, community-maintained servers exist
Reuse existing Node/Python MCP serverMCPPlug in via JSON or CLI in 10 seconds
Access JARVIS internals (memory, session, HITL)NativeMCP tools run in isolated subprocess and cannot touch JARVIS state
Extremely low latency tool (<100ms)NativeMCP adds IPC overhead per call
Reversible, stateless operationMCPSimplest to build and maintain

If unsure, start with MCP. Only write a native tool when MCP genuinely does not fit.

Adding an MCP tool (recommended)

MCP tools are external servers that JARVIS spawns as subprocesses. They speak the Model Context Protocol over stdio, SSE, or streamable HTTP. JARVIS exposes every discovered tool to the AgenticBrain as mcp__<server_name>__<tool_name>.

Method 1 — CLI (fastest)

Run these commands from any terminal. If JARVIS is running, changes hot-reload within 2 seconds with zero restart:

terminalpowershell 
jarvis mcp add everything npx @modelcontextprotocol/server-everything
jarvis mcp add github npx @modelcontextprotocol/server-github -e GITHUB_PERSONAL_ACCESS_TOKEN=ghp_xxx
jarvis mcp add remote_docs https://example.com/mcp/sse -H Authorization="Bearer xxx"
jarvis mcp list
jarvis mcp test github
jarvis mcp disable github
jarvis mcp enable github
jarvis mcp remove github

What happens under the hood

  1. Startup or hot-reload — MCPManager reads Data/mcp_servers.json
  2. Spawn subprocess — each server runs in its own isolated process via MCPClient + AsyncBridge
  3. JSON-RPC handshake — initialize then tools/list discovers schemas
  4. Schema conversion — each MCP tool becomes a Gemini FunctionDeclaration
  5. Namespacing — exposed to the LLM as mcp__<server>__<tool>
  6. Runtime dispatch — when the agent calls an mcp__ tool, the executor routes it through MCPManager to the correct server
check_circle

Zero restart required. MCPWatcher polls the config file mtime and hot-loads or unloads servers within ~2 seconds. You can add, remove, enable, or disable servers while JARVIS is running.

warning

Windows npx resolution. JARVIS auto-resolves npx shims to node.exe + npx-cli.js and injects -y automatically. No cmd /c wrappers needed — just pass npx and the package name.

Adding a native tool

Native tools live inside JARVIS process space. They can access memory, session state, and HITL confirmation gates. Two files need edits: Prompts.py to declare the schema and executor.py to handle the call.

Step 1 — Declare the tool schema

Open core/brain/Processor/Prompts.py and find the get_native_tools() function. Add a new types.FunctionDeclaration inside the returned types.Tool(function_declarations=[...]) list:

descriptionPrompts.py — get_native_tools() 
types.FunctionDeclaration(
    name="weather_action",
    description=(
        "[WHEN TO USE]: Fetch current weather for a given city.\n"
        "[WHEN NOT TO USE]: Do not use for historical weather or forecasts beyond today."
    ),
    parameters=types.Schema(
        type=types.Type.OBJECT,
        properties={
            "city": types.Schema(
                type=types.Type.STRING,
                description="City name, e.g. Mumbai or New Delhi"
            ),
            "unit": types.Schema(
                type=types.Type.STRING,
                description="Temperature unit: 'celsius' or 'fahrenheit'"
            )
        },
        required=["city"]
    )
)
info

Return format matters. The description should start with [WHEN TO USE]: and [WHEN NOT TO USE]: sections — this is how every existing native tool is documented inside get_native_tools(). Following this convention helps the LLM route correctly.

Step 2 — Register the handler

Open core/brain/executor.py. Locate the tool dispatch table (usually a dictionary mapping tool names to callables, referenced by execute_single_tool_sync and execute_tools_parallel). Add an entry for your new tool:

descriptionexecutor.py — dispatch pattern 
def _handle_weather_action(params: dict) -> str:
    city = params.get("city", "").strip()
    unit = params.get("unit", "celsius").strip().lower()
    if not city:
        return "[ERROR] Missing required parameter: city"
    try:
        url = f"https://wttr.in/{city}?format=j1"
        response = requests.get(url, timeout=10)
        data = response.json()
        temp_c = data["current_condition"][0]["temp_C"]
        desc = data["current_condition"][0]["weatherDesc"][0]["value"]
        if unit == "fahrenheit":
            temp_f = round(float(temp_c) * 9 / 5 + 32)
            return f"[OK] {city}: {temp_f}°F, {desc}"
        return f"[OK] {city}: {temp_c}°C, {desc}"
    except Exception as e:
        return f"[ERROR] Weather lookup failed: {e}"


TOOL_HANDLERS = {
    "weather_action": _handle_weather_action,
    "system_controller": _handle_system_controller,
    "file_operations": _handle_file_operations,
}
warning

The exact dispatch mechanism varies by JARVIS version. Open core/brain/executor.py and look at how system_controller is handled — then mirror that same pattern for your new tool. The dispatch table may be a dict, an if/elif chain, or a class method map.

Step 3 — Restart JARVIS

Unlike MCP tools, native tools are loaded once at module import. After editing both files, restart JARVIS with Ctrl+C then jarvis. On the next agent loop, the LLM will see weather_action in its tool list.

Conventions and best practices

  • Return format: Always return a string starting with [OK] or [ERROR] so the LLM can parse success vs failure.
  • Timeout: Wrap network calls with explicit timeout=. Never let a tool hang the agent loop.
  • Idempotency: If the tool modifies state, make it reversible when possible.
  • HITL gate: If the tool is irreversible (sends money, deletes data, sends external messages), it must raise a HITL confirmation before executing.
  • No side effects in schema: The parameters block is pure data description — no logic, no defaults evaluated at schema build time.
  • Naming: Suffix tool names with _action or _command to match existing convention (weather_action, email_action, image_command).

Testing your tool

Before wiring it into the full agent loop, test the handler standalone:

terminalpowershell 
python -c "from core.brain.executor import _handle_weather_action; print(_handle_weather_action({'city': 'Mumbai', 'unit': 'celsius'}))"

If that returns clean output, restart JARVIS and test through the agent:

"Jarvis, what's the weather in Mumbai?"

Open the Agent Panel — you should see weather_action execute and return the observation. If it does not appear, verify the tool name in get_native_tools() matches the key in your handler dispatch exactly.

check_circle

MCP tools auto-appear. If you chose the MCP path, you do not need to touch Prompts.py or executor.py — the tool appears as mcp__<server>__<tool> automatically after a hot-reload.

Migrating between machines

  1. On old machine — run the backup command above.
  2. On new machine — install JARVIS, then jarvis reset --hard to clear any auto-generated data.
  3. Extract backup — copy the zip and extract into Data/.
  4. Re-authenticate — run jarvis login --all because tokens are machine-bound.
  5. Rebuild RAG index — delete Data/jarvis_memory/rag_chroma_db and rag_hashes.json, then restart JARVIS. It rebuilds automatically.
  6. Verify — check that memory recall works: "What do you know about me?"
